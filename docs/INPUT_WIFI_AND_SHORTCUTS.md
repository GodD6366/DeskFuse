# Wi-Fi 主控选择与紧急收回快捷键

## 使用

1. 在启动授权面板或「设置 → 权限 → 读取当前 Wi-Fi」授权。macOS 使用定位服务权限保护 SSID，DeskFuse 只读取已连接网络名称，不请求位置更新、不扫描周边网络。系统定位服务关闭、授权被拒绝和当前没有 Wi-Fi 是不同状态。
2. 在键鼠共享设置中保存「此设备作为主控」，根据需要显式开启共享、添加参与设备。授权本身不会开启共享。
3. 在「共享设置 → 按 Wi-Fi 自动选择主控」选择已配置的主控，勾选「记住当前 Wi-Fi」，点「使用此主控」。须等网络名称完成读取和稳定等待；陌生网络的选择不自动持久化。
4. 有保存规则后，匹配网络恢复所选主控；无匹配规则时暂停本机主控，回到匹配网络时恢复。原有角色、共享开关、快捷键和布局保留。没有规则时沿用手动模式。
5. 自动暂停后仍可进入共享设置修改/删除规则，也可选择「本次使用此 Mac 作为主控」。临时选择在下一次网络场景变化时清除，不覆盖已保存规则。

## 紧急收回

- 键鼠共享页不再放置需要鼠标点击的紧急按钮，改为「快捷键设置」入口。
- 「设置 → 快捷键 → 编辑键鼠快捷键」或「共享设置 → 快捷键」可以修改第六项「紧急收回」，保存后生效。配置被拒绝时不直接关闭编辑面板。
- 自定义组合必须包含 Command、Option 或 Control，不能与方向/锁定、剪贴板唤起、暂存区或启用的工作流快捷键冲突。
- 固定 `Control-Option-Command-Escape` 始终可用，作为自定义配置之外的保底；可通过「恢复默认紧急收回快捷键」还原。
- 原生事件捕获直接识别紧急组合，先恢复光标，再释放控制；被控角色和快捷键录制期间也不禁用紧急收回。组合键不作为普通按键转发给对端。
- 旧配置缺少紧急快捷键字段时使用固定默认值，不重置其他快捷键。

## 实现边界

- SSID 在取得定位授权的主程序读取，每 5 秒观察一次，经受限的主程序/输入服务 IPC 交给环境状态机；输入服务不再竞争读取同一个 SSID。
- 网络场景稳定 10 秒后切换；存在正在使用的输入租约时延后交接，避免中途转移按键。切换时释放旧控制，不把 Wi-Fi 名称当作设备信任凭据。
- 仍支持有线设备采用可信对端提供的唯一 Wi-Fi 场景；因此拔掉本机 Wi-Fi 不一定等于离开场景。多个场景/主控冲突时提示选择，不随意接管。
- 修改的是有效主控选择，不自动打开已关闭的共享开关，也不覆盖用户手动紧急收回产生的暂停状态。首选主控离线时不自动抢占。
- 本次未更改远程应用窗口自身的 `Control-Option-Escape` 释放快捷键。

## 验证

自动测试覆盖旧快捷键配置迁移、冲突拒绝、自定义与保底组合释放输入、被控角色的紧急按键识别、Wi-Fi 观察 IPC 放行、网络进入/离开/返回、主共享开关保持关闭、稳定等待及临时选择过期。Swift 测试只检查权限状态映射与界面配置，不请求真实权限。

实机仍需验证：定位拒绝后再次授权、定位服务总开关、重启后的 SSID 读取、两台 Mac 切换真实 Wi-Fi、鼠标在对端时的自定义及保底紧急组合、修改冲突按键后保存错误提示。构建与状态机测试不等于已完成这些验收。
