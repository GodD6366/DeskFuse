# DeskFuse Windows 全功能与局域网永久自动更新

- 方案确认：2026-09-06。
- 目标平台：macOS arm64、Windows 11 x64；2026-09-11 调整为 Rust 共享引擎 / 平台原生 UI。
- 本文件为实施契约。末尾进度表区分已经实现与尚未接入，不把设计当成运行结果。

## 1. 目标与交付边界

Windows 对齐配对、文字/图片/文件同步、暂存抽屉、原生拖放、双向键鼠和多显示器跨屏；输入包括普通桌面、管理员窗口、锁屏、系统登录和 UAC 安全桌面。不新增屏幕传输，不覆盖 BIOS、BitLocker 开机前解锁或 macOS 登录前控制。

局域网更新以用户手动触发为主，后台每 12 小时主动扫描一次；没有调试模式、更新开关或逐次安装确认。Mac 可以缓存分发 Windows 包，Windows 也可以缓存分发 Mac 包。发现可信邻居所持有的兼容新版后自动下载、在安全安装点自动替换并重启。

开发方负责代码、相关自动检查、构建、签名状态和安装包完整性；用户负责 Finder/Explorer、两机、多显示器和安全桌面的真实验收。未验收不阻止交付测试包，但不得标记为已通过。

## 2. 平台边界

新增 `deskfuse-platform` 公共接口层与 Windows 原生适配器；保留 macOS 实现。业务逻辑不依赖 AppKit、Quartz、Win32 或 SwiftUI 平台细节；组成入口选择适配器。迁移期间 macOS crate 可以重新导出旧名称，以保持调用及序列化格式兼容。

| 接口 | 职责 |
| --- | --- |
| Clipboard | 变更监听、快照读写、来源标记、通用格式转换 |
| FileExport | 已有文件导出、按需文件提供、原生粘贴/拖出生命周期 |
| InputCapture / InputInjector | 采集、注入、回环抑制、释放全部输入、紧急收回 |
| DisplayTopology | 稳定显示器 ID、布局、缩放、旋转和坐标转换 |
| SessionCapabilities | 普通、锁屏、登录、安全桌面的真实能力及阻碍 |
| DeviceIdentity | 稳定身份、公钥、签名和系统存储 |
| UpdateInstaller | 检查、暂存、替换、启动确认和回滚 |

托盘、原生窗口、菜单、拖放桥接属于应用平台 UI。未实现能力必须返回明确的不支持状态，禁止成功空实现。当前剪贴板的 native items 仅作为同平台增强，不能作为跨平台通用线格式。

### 2.1 Windows 进程

1. 普通用户桌面进程：平台原生 UI（Windows WPF 已有分阶段实现）、托盘、剪贴板格式解码、图片和用户文件处理、抽屉、用户设置。
2. Windows Service：开机启动、稳定身份、共享网络运行时、会话管理、输入授权、安装协调。
3. 输入辅助进程：服务在指定会话/桌面创建和回收，执行固定输入操作，无任意命令接口。

服务统一持有设备身份和网络运行时，桌面进程经受限 Named Pipe 连接。必须校验客户端进程身份及会话归属，并在会话切换时丢弃旧会话内容。服务不把上一用户的剪贴板和文件内容交给下一用户。

Windows 设备密钥由服务保管，使用系统保护存储及服务/管理员目录 ACL，普通桌面进程通过明确的身份接口使用，不获取私钥。macOS 使用权限为 `0600` 的本地身份文件，保持 `com.deskfuse.app` 和既有签名选择，禁止通过重建身份解决错误。

登录/安全桌面只允许此前配对且获得输入授权的设备。锁屏停用剪贴板和用户文件能力；输入资格单独判断。注销、桌面切换、辅助进程异常和断线都释放按键、鼠标及租约。服务位于 Session 0，不能直接把服务当成交互桌面程序。

### 2.2 剪贴板、文件与抽屉

通用格式为文字、PNG、HTML、RTF、文件引用；原生 UTI 和 Windows 注册格式仅用于平台转换，同平台可保留增强格式。文件引用优先于附带的路径文本，不把来源机器的绝对路径写入目标剪贴板。

Windows 已有文件使用原生文件数据对象；尚未下载文件使用 OLE 虚拟文件与异步内容提供。专用 STA/OLE 线程持有数据对象，通过异步桥接供给数据，不在 GUI 主线程下载文件。保留既有提前传输、配额、取消、去重和旧任务不得污染新剪贴板的契约。

接收前检查 Windows 保留名、非法字符、大小写冲突、路径长度及逃逸；无法保持名称的任务明确拒绝，不静默重命名或覆盖。清理只处理应用自有缓存，保护接收、粘贴和导出任务。

Windows 补齐托盘、摇动触发、抽屉拖入/拖出，保留 240 × 240 暂存抽屉和二级发送菜单。信息架构沿用当前设计，材质采用平台原生方案及可读回退。

### 2.3 输入与显示器

新能力版本采用 USB HID Usage 表示物理键，修饰键独立编码。默认物理位置对应：Command↔Windows、Option↔Alt、Control↔Control；输入法由接收端解释，不自动把所有 Command 组合改成 Ctrl。应用自己的复制/粘贴则使用目标平台语义快捷键。

平台层将每屏 DPI、旋转、负坐标和原生像素转换为统一逻辑坐标。Mac 保留既有紧急收回；Windows 使用 Ctrl+Alt+Win+Esc，并提供托盘收回。

新旧 Mac 可协商旧 Quartz 协议，Windows 不执行旧 Quartz 键码。不支持新版输入时只禁用相应能力。Ctrl+Alt+Del 使用独立系统能力路径，策略禁止时报告不可用，不修改系统保护。

## 3. 发行与信任

新增 `deskfuse-update`，集中管理模型、签名、包验证、候选选择、独立缓存和更新状态机。

- `ReleaseVersion`：SemVer、单调 `build_number`、唯一 `release_id`。
- `ArtifactDescriptor`：系统/架构、包类型、文件名、大小、SHA-256、最低系统版本。
- `ReleaseManifest`：版本、平台包列表、协议兼容范围。
- `SignedReleaseManifest`：明确格式版本与 Ed25519 发行签名；固定字段序列化、域分隔，拒绝未知字段。
- `UpdateStatus`：更新事务、目标、阶段、字节进度、失败原因。

SemVer 按优先级比较，随后比较发行编号；不使用 Git 提交数，不把构建元数据当新版本。相同版本/编号出现不同发行 ID 或包哈希是冲突，不任选其一自动安装。同次 Mac/Windows 发行使用同一编号。发行协调端串行分配编号并持久化；失败编号不回收。

配对证明发送设备身份，发行签名证明更新内容的授权，二者不能替代。发行私钥只在协调端的仓库外受限目录保存，不进入源码、安装包、日志或 Windows 构建机。公钥随基础应用固定；拒绝从网络清单导入信任根。平台代码签名、公证和内部发行签名分别记录。

## 4. 局域网自动同步

### 4.1 发行包

- Mac 首次安装为 DMG，更新为保留签名和应用结构的归档。
- Mac 手动安装的 `.app` 内携带本次发行的原始签名更新归档和清单，拖入 Applications 并推出 DMG 后仍可向可信设备提供安装包。归档包含不内嵌更新归档的基础应用，避免递归打包；自动更新安装基础应用，并在独立更新缓存保留原始归档用于继续转发。
- Windows 为 NSIS 完整离线 EXE，支持固定无人值守安装流程。
- 发布清单声明实际存在的平台包，不用空路径或虚假状态代表未构建平台。
- 任意可信设备导入并验证原始包后可以转发；转发不重新压缩或改动字节。
- 没有更新协议的旧版需要先手动安装一次基础包。

### 4.2 协议

在现有签名 Hello 中仅协商新能力位，不改变其签名正文。认证后交换 `ReleaseInventory`；支持 `UpdateRequest`、`UpdateChunk`、`UpdateCancel`、`UpdateStatus`、`UpdateReceipt`。旧端未声明能力不发送新消息。

独立消息类型和更新缓存复用分块、校验、取消及进度基础组件，禁止把更新包塞入剪贴板载荷、剪贴板历史或普通接收流程。消息、清单和块均有长度上限；库存不能仅凭摘要进入可安装候选，必须验证清单签名及本机兼容性。

发送和接收都要求配对、更新能力和当前会话的物理局域网证据；不能以 mDNS 或私有 IP 代替路由判断。VPN、Tailscale、未知路径拒绝提供更新；路由变更重新检查。保留全局默认关闭的公网功能边界。

不选举全网主节点。每台设备独立选择可见可信邻居持有的最高兼容、已验证发行。每机一个更新事务，相同包去重；传输源断线可重新从其他来源获取，首版不做多源分片拼接。不能因网络断线把本地启动成功判断为失败。

### 4.3 状态机

```text
发现 → 下载 → 验证 → 等待安全点 → 暂存 → 停止旧进程
     → 安装 → 启动自检 → 本地成功 → 等待重连确认 → 完成
                    ↘ 安装/自检失败 → 恢复旧版 → 隔离该发行
```

- 手动“检查更新／立即下载安装”立即唤醒同一个任务；后台扫描间隔为 12 小时（从上次扫描完成起算），失败不进行高频重试。启动仅准备一次本地已验证清单，不立即扫描其他设备。
- 本地启动、手动／周期扫描和成功下载后刷新已验证清单；对端查询遇到尚未准备好或无可分发包的清单时，按需导入应用内置包及本地来源。已有可分发清单时查询只读完整快照，避免反复整包哈希阻塞传输。刷新串行执行并合并并发请求，完整替换前保留上次已验证快照；实际分发及安装仍保留完整性校验。
- 不增加调试模式、更新开关或逐次安装确认；下载和安全安装点规则保持不变。
- 普通主动安装在活跃接收/粘贴/导出期间等待；更新页的“立即安装”可跳过这段等待并直接进入安装切换。自动安装另须等待远端控制结束；用户主动下载安装时，在新版就绪后通过输入线程正常收回控制、释放按键与租约，不等待用户手动结束键鼠共享。切换到安装态时关闭新任务入口并再次检查，防止检查后新任务进入。
- 替换前释放全部输入和租约，持久化事务。
- 权限、磁盘或系统阻止时保留旧应用，报告具体原因，不循环申请权限。
- 完整性验证后仍需在安装边界重新验证实际载荷，防止验证后被替换。
- 自检期限为新程序启动后 60 秒；自检前不接受业务写入和网络任务。
- 本地自检失败回滚；网络不可用只延迟远端回执。
- 回执必须匹配版本、build、release ID、目标及产物哈希；下载完成不能表示安装成功。
- 隔离只针对产物本身：签名、载荷校验或启动自检失败才隔离该发行，不立即反复安装，更新发行可继续评估。安装被中断（断电、强制退出、退出超时）不是产物证据，回滚后该发行仍可选择。
- 回滚记录与当前安装版本核对。已安装版本等于或高于回滚发行时，该记录和对应隔离项按历史清理，不再重复报告上次失败。
- 安装交接以 helper 已启动为前提：helper 无法启动或进程未按期退出时取消交接、重新开放命令入口并保留当前版本，客户端不进入只能手动退出的“正在安装更新”状态。

独立更新缓存默认 4 GiB，保护活跃下载、暂存和回滚内容，优先保留当前候选及上一版。下载先预留全包空间，并计算安装解包/备份所需空间；容量不足不开始安装。缓存租约不得由不可信路径直接指定。

### 4.4 安装回滚

Mac 使用独立 helper 等待旧进程退出，验证目标身份和解包结果，备份旧应用后替换；新版本启动确认后清理旧包。不可写位置由系统授权处理，不能先删除旧应用。

Windows 初次提权安装服务；后续服务只启动发行验证通过的固定安装器。安装器负责服务、输入辅助进程及 GUI 全套更新；外部安装进程持有回滚责任，不能依赖正在被替换的服务继续存活。

事务同时覆盖程序和必要数据库迁移。新进程自检前不接收业务写入；迁移失败恢复相应数据备份。成功后不可因远端离线回滚用户新数据。升级不删除配对、本地身份文件、服务身份和用户文件。

## 5. 构建与交付

阶段顺序：

1. 文档、平台公共边界、发行/更新模型、协议契约及回归。
2. Windows 构建机接入、原生客户端、服务骨架、托盘、安装器；及早验证系统桌面输入可行性。
3. 优先打通双平台永久自动更新，交付首次手动安装基础包。
4. 剪贴板、Explorer 按需文件、抽屉及缓存对齐。
5. 输入编码、多显示器、登录及安全桌面功能。
6. 自动检查与阶段性安装包交付，不等待开发方真机验收。

Windows 使用用户提供的构建机：OpenSSH + PowerShell + MSVC x64 Release。脚本同步确定的源码快照、构建、打包和回收产物；构建机不持有发行私钥。不擅自使用 GitHub Actions 或发布公开 Release。

同一发行固定依赖锁文件、Xcode/SDK 版本与 UniFFI 锁定版本、源码快照及发行编号。保留当前脏工作区，不用清理或覆盖用户文件获得“干净版本”。安装包不得包含凭据、日志或本地配置。

交付：Mac DMG、Windows x64 EXE、原始更新归档/安装器、签名清单、版本/build、SHA-256、平台签名/公证状态、检查结果和用户验收清单。

## 6. 检查矩阵

开发方：相关 Rust 测试、项目检查脚本、Windows Release、原生包内容/架构/版本/服务/helper 配置及哈希。自动回归覆盖旧协议、映射、路径、签名、错误目标、冲突发行、重复包、断线、取消、容量、安装失败、启动超时、回滚及远端回执。不得执行安装来替代用户指定的真机验收。

用户：Finder/Explorer 复制/菜单粘贴/拖放、大文件按需、双向输入、输入法、100/150/200% DPI、多屏、休眠、UAC/登录、跨系统包转发、更新等待、断网和恢复。

诊断仅包含元数据、版本、哈希、阶段、错误码和状态，不包含剪贴板正文、文件内容、按键内容或密钥。

## 7. 当前交付边界

macOS arm64 已接入完整客户端更新流程：可信物理局域网库存交换、独立分块下载、签名与完整性验证、带发送保护的缓存回收、文件/原生导出/输入空闲安装、独立 helper、数据库与应用备份、60 秒 SwiftUI 启动自检、失败回滚和持久化隔离，以及重连安装回执。设置页和设备页提供本机“立即下载安装”：立即唤醒检查并下载兼容新版，下载中点击会加入当前任务，已下载时显示“立即安装并重启”。主动请求在当前尝试结束、无兼容新版或失败后失效，不延续到未来发行；安装就绪后由输入线程结束键鼠控制、释放按键并停用捕获，普通主动请求会等待文件传输、粘贴和原生导出完成，点击“立即安装”则跳过这段等待。界面显示真实下载字节、目标版本和等待原因。“检查更新”及原有自动下载、空闲安装保留；失败发行在验证或自检失败时隔离，被中断的尝试不隔离，已经安装到位的回滚记录连同其隔离项按历史清理；本机打包自动签发更新载荷、归档 NAS 并提供本机分发种子。没有更新协议的旧版仍须逐机手动安装一次基础包。自动检查和隔离应用副本的安装演练属于开发验证；真实两机下载、断网重连和使用中等待仍由用户验收。

Windows 已新增原生 WPF 桌面、托盘、当前用户历史和本地暂存区，设备配对及受限业务 IPC 已接入服务；文字/图片/富文本经 clipboard-sync-v2 与原生写入回执交接，当前最多 16 MiB。普通已解锁桌面已接入独立 42425 input-only runtime 与用户态 helper，当前阶段先支持 Mac 主控到 Windows 被控，带 1.5 秒原生释放看门狗和紧急收回。首次手动安装的 NSIS 脚本已提供。**尚未全功能对齐**：远端文件/OLE、Windows 主控、高完整性/安全桌面输入、自动升级/回滚、工作流和 Windows 原生安装/两机验收仍未完成。完整进度见 [WINDOWS_CLIENT.md](WINDOWS_CLIENT.md)，当前 IPC 见 [WINDOWS_DESKTOP_IPC.md](WINDOWS_DESKTOP_IPC.md)；旧服务检查点见 [WINDOWS_SERVICE_CHECKPOINT.md](WINDOWS_SERVICE_CHECKPOINT.md)。

GitHub 0.4.0 预发行提供 macOS arm64 DMG 和 macOS x86_64 DMG；Windows 构建暂跳过。版本由提交的 release.json 描述，构建机不分配编号。发行私钥与 ledger 不进入 CI；未签名的 update ZIP 不公开为 LAN 更新载荷。参见 [发行指南](RELEASING.md)。
