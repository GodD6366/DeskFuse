## 已接入的配置

- `config/deskfuse.json` 指定目标名称和当前发行配置文件。
- `config/legacy/distribution.json` 保存仍在工作的仓库、资产、Cask 与安装名称。
- Rust 引擎在构建时生成更新器地址常量，配置变动会重新触发构建。
- `release.py`、`update-cask.py` 和发布工作流从当前配置读取发布仓库与 DMG 名。
- 发布仓库中的官网使用生成的配置；下载优先选择目标资产，其次当前与历史资产。
- Cask 后续任务同步官网配置，但不会改写历史 Release。
- `scripts/check-branding.py` 默认严格检查受 Git 管理及未忽略的新文件，包括路径、
  内容和符号链接目标。目前严格检查应失败；不能将 `--report` 作为完成证明。

生成官网配置：

```sh
python3 scripts/distribution-config.py --website-output "$DISTRIBUTION_ROOT/web/src/config/legacy/distribution.json"
python3 scripts/distribution-config.py --website-output "$DISTRIBUTION_ROOT/web/src/config/legacy/distribution.json" --check
python3 scripts/check-branding.py --report
```

仓库 slug 切换时只修改当前配置里的仓库值，再重新构建客户端、同步官网配置。
目标仓库字段不会提前改变下载流量。已经安装的二进制仍包含旧地址，不能靠修改
仓库里的 JSON 远程改变它们；其退场仍需要桥接发布和旧地址过渡入口。

## 桥接发布的实际阻碍

现有公开更新器固定选择旧 arm64 DMG 文件名。安装器还固定检查旧 `.app`、
可执行文件、Bundle ID 和旧应用的指定签名要求。仅让新更新器接受两种身份，
不能让尚未升级的旧更新器识别新名字发行物。

因此“旧版自动升级至桥接版”和“桥接版只发布新名字资产”不能同时成立。
后续需要确定：桥接发布是否允许临时保留一个旧命名兼容发行包，或者要求用户
手动安装桥接版。兼容包不是简单复制新包并改 DMG 文件名，内部应用身份与
签名也必须通过已安装旧客户端的检查。既有已发布资产仍保持不可变。
