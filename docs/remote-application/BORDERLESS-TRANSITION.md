# 应用主体窗口、候选窗与无黑帧切换

用户截图显示上下大块留黑、候选窗越出应用主体后的右侧空白，以及「画面配置正在变化」提示。源码存在两个独立原因：固定尺寸本地窗口进行等比适应产生留边；候选窗扩大采集区域后，整个联合区域被直接显示。切换配置时 `LatestVideoFrame.reset` 清空可见帧，等待新解码器期间主动呈现黑色。

## 修改

- 捕获描述增加应用主体与越界辅助窗口的位置。普通应用主窗口决定显示主体，候选窗不再决定本地窗口比例；采集仍保留其原始位置和原生像素。
- A 在 Metal/Core Image 路径裁出应用主体，将越界候选窗合成到窗口内。移动后的候选窗有独立命中区域，点击坐标映射回 B 原始位置。辅助窗口布局更新不重建编码器或重新申请输入租约。
- 适应模式下，本地普通窗口按已呈现应用主体的比例调整并约束拖动比例，使用实际内容布局尺寸扣除系统标题栏/工具栏。保留原有 1:1 查看和全屏的适应行为。
- 配置换代只更新期望的 surface，最多保留上一帧和对应布局。新 surface 的第一帧不受旧 surface 的序号限制；新解码结果与布局一起原子发布。旧帧不能确认新配置，也不能继续注入旧坐标；停止或真正错误仍清空画面。
- Host 在发送新 surface 前发布输入几何，避免第一帧已被 A 呈现、Host 却仍按旧几何拒绝控制的竞态。静止画面也可触发新配置的自动控制申请。

按用户既有要求，只做官方构建、固定本地签名与包完整性检查，不运行本机交互测试。候选窗显示/点击、输入连续性、窗口尺寸和视觉效果待双机验收。

## 候选框越界反馈的后续修正

用户补充截图中候选框超出应用主体右侧，周围仍有黑色空间。截图本身不能确认两端运行的 build 或接收到的布局，不能据此认定唯一运行时根因。本轮补上以下边界约束与可诊断信息：

- ScreenCaptureKit 显式将 `sourceRect` 填入完整编码像素区域，关闭采集端额外的等比留边。A 仍负责等比展示；编码器偶数像素取整不会再产生另一层隐藏边距。
- GPU 合成后的候选框及整张图都裁到应用 viewport，越界候选框继续完整向内移动；点击沿用移动后命中区域到 B 原始坐标的映射。
- 渲染器直接比较帧布局，静止画面仅更新候选框位置也会重绘，不依赖 SwiftUI 恰好触发刷新。
- 仅更新应用名称不再将原生窗口重置为 1100 × 720。窗口内容布局变化后会重新校正比例，同时用尺寸误差检查避免递归调整。
- 两端在配置或布局变化时记录 `surface_layout`，包含 generation、capture、application 和 auxiliary 几何；不记录输入内容或候选文字。

沿用只交包自测的要求，不运行本机交互或自动化测试。待双机验证：右/下边缘超长候选框完整显示、候选点击映射、首次打开/重连后的窗口比例、打字期间无黑闪。
