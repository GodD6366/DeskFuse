# 多应用窗口与原生应用选择器

## 用户可见行为

- 设备上的「远程应用」打开独立选择器。选择一个应用后，新建对应远程窗口；选择器保留，可以继续打开其他应用。再次选择同一设备的同一应用会前置已有窗口，不重复创建会话。
- 每个远程窗口独立持有媒体通道、编解码器、画质设置、连接状态和关闭生命周期。关闭一个窗口不退出 B 上的应用，也不影响其他远程窗口。
- 当前聚焦的远程窗口取得键鼠控制，其他窗口继续显示。B 仍只有一个系统前台和一个输入租约。主控失焦释放自己的控制；旧窗口延迟到达的失焦、停止回调不会清除新窗口的本机独占状态。
- 最小化只暂停该窗口采集，保留会话和上一帧；恢复时发送新画面配置，在新画面就绪前禁止旧坐标输入。
- 应用列表采用可搜索图标网格，运行中的应用排前并用分隔线与其他应用分开。分类使用 B 应用 bundle 的 `LSApplicationCategoryType`，未提供分类的归入「其他」，不凭名称猜测。
- 图标来自 B 端 `NSWorkspace`，以 128px PNG 传输；单图最多 48 KiB，列表图标预算约 6 MiB，B 图标缓存最多 8 MiB / 512 项。缺失图标使用系统 App 符号。
- macOS 26+（包含当前 SDK 27）使用系统 `glassEffect`、`GlassEffectContainer` 和原生玻璃分类按钮，保留窗口关闭、拖动和缩放；macOS 14/15 与降低透明度有系统材质/实色回退。
- 支持搜索回车打开首个匹配项、方向键选择、回车打开；已打开应用显示标记。

## 实现边界

- 不新增配对流程。各应用通过同一已认证 QUIC 连接建立独立有界流，传输层待接收会话队列由 2 扩为 16；B 最多接收 16 条远程应用会话（包含列表连接）。
- A 的窗口管理器统一维护本机输入独占归属；B 在同一已配对主控的应用之间交接控制，另一台设备不会抢占现有控制者。原生输入服务继续校验 peer、session、generation 和前台 PID。
- B 的各路采集只在目标应用处于前台时包含系统输入法窗口，避免前台应用候选词出现在其他远程窗口中。
- 并行原生高分辨率视频会共享两台设备的硬件编码、解码和网络资源，本次没有完成多路性能验收。
