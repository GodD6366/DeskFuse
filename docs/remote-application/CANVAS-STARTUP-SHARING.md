# 无标题栏画布、首次打开与退出控制

## 用户反馈与修改

build236 截图显示 A 本地标题栏仍占一整行，视频的应用圆角外是黑色；用户同时报告初次启动需要手动重连、初始窗口比例不合适、退出远程模式后鼠标共享未及时恢复。

- A 的远程画布改为可聚焦、可缩放的原生无标题栏窗口，关闭黑色窗口背景。悬停时显示小型操作浮层，保留移动本地窗口、画质、最小化、关闭等操作；画面中 B 的标题栏拖动仍转发到 B。
- Metal 输出及窗口支持透明。H.264 不携带 alpha，渲染器在 GPU 上按应用坐标生成 20 pt 圆角遮罩，清除四角外部的黑色填充，不对应用正文做黑色抠图；鼠标命中区域使用同一圆角。圆角半径随显示比例变化，桌面模式不套应用圆角。
- 初次收到画面配置后，使用 B 的应用逻辑尺寸而非编码像素决定 A 初始大小。原尺寸可容纳时不放大，超出当前屏幕可用区域则等比缩小；后续手工缩放保留，跨屏时重新约束到屏幕内。禁用 HostingController 的自动尺寸推导，移除 1100 × 720 初始画布。
- 新窗口在连接尚未开始时也显示加载态，不先闪现「无法打开应用」。Host 启动完成后等待 ScreenCaptureKit 登记窗口，针对 `noWindow` 每 250 ms 重试，最多 30 秒；等待期间后台监视器不抢先判定启动失败。权限、编解码等真正错误不被无限吞掉。
- 首帧前的连接失败最多自动重试 3 次（等待 0.5 / 1 / 1.5 秒），沿用原先选择的应用；关闭窗口取消重试，连接重新建立后创建新的会话身份，不重放输入。首帧后不把所有运行时断连都当成启动失败。
- 释放控制默认同时解除 A 的共享暂停。鼠标移出画布、失焦、最小化、错误与控制超时均走此路径，通过已有本机输入服务紧急控制通道恢复，不等待 B 端响应。只有多窗口控制权交接明确保留暂停，旧窗口不能解除新窗口的暂停。
- 自动获取控制前检查鼠标仍位于当前画布内，避免鼠标已经退出后被延迟的首帧回调重新拉回远程模式。
