# 鼠标离开远程应用后恢复共享

## 定位与修复

build240 用户反馈鼠标离开远程应用窗口后仍无法使用鼠标共享。源码检查发现以下缺口，尚未做双机复现归因：

- 原协调器仅停止采集/注入，未向共享协议报告不可用。空闲共享连接继续保持 Ready，而本地 grant 的 1.5 秒观察窗口在暂停期间停止更新；恢复后旧 grant 被永久标记失效，原生适配器重新启动并不能恢复该连接。
- A 的解除暂停先尝试 `7 -> 0`，再尝试 `6 -> 0`。若协调器恰好在两次操作之间完成 `6 -> 7`，两次都失败，输入会继续暂停。B 的 `4/5` 释放也有同类竞态。
- 原画布仅依赖 `mouseExited`，跟踪区域未启用拖拽期间退出事件；画面外的移动又直接被丢弃，无法补发控制释放。

本次修改：

1. A/B 进入远程应用独占时向共享协议报告 Preparing，使协议撤销旧输入租约；清理本地 grant 缓存并保留旧 session 的拒绝记录。退出后立即触发原生能力刷新，使用新的共享租约恢复，不修改用户共享开关或清除用户紧急暂停。
2. A 的 `6/7`、B 的 `4/5` 释放改用原子更新，退出请求不会被并发暂停确认覆盖，也不会解除更新或其他角色持有的暂停。
3. 画布增加拖拽退出事件；移动事件落到实际圆角画布外时立即释放。仅在画布持有焦点时，以 50 ms 定时器在 common run-loop modes 检查实际指针位置，兜底处理漏发退出事件、透明圆角和窗口移动。退出/失焦/移除视图时停止定时器，取消自动获取控制及按键状态，不等待 B 返回。
4. 日志增加 `canvas_exit_tracking_exit`、`canvas_exit_pointer_event`、`canvas_exit_pointer_boundary`，以及输入子进程的 `remote_sharing_pause` / `remote_sharing_resume`，可区分边界检测与共享协调器恢复。

## 验证范围

按既有用户要求不运行本机交互或自动化测试，仅执行官方构建、固定本地签名和 DMG 完整性检查。双机待检查：远程操作超过 2 秒后移出窗口，连续重复进出，按住鼠标拖出，移过透明圆角，以及打开多个远程应用后切回普通跨屏共享。50 ms 为边界兜底检查间隔，并非已经测得的端到端共享恢复延迟。两端均需安装本次包以覆盖 A/B 的租约恢复修复。
