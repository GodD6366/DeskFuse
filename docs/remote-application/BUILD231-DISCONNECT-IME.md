## 中断证据与修正

- A 在 1789715923913 收到 `controlReady`，1789715924069 仍为 `healthy=true`、heartbeatAgeMs=220、sentInput=28；1789715924105 出现 `transport_closed`。
- 对应 B 在本机时间 1789715923982 先关闭 transport，再释放仍处于 pause=5 的输入租约。另一次 A 1789715938779 / B 1789715938650 也为同一顺序。两机时钟有约 120ms 偏差，不用裸时间戳判定跨端先后。
- 没有证据表明这两次由前台切换或权限撤销发起。旧 `transport_closed` 未记录具体异常文字，因此不能仅凭日志宣称某个队列就是现场唯一原因。
- 源码确定存在瞬时满队列即断开：QUIC 与 Swift 之间收发队列各 3 个槽，`try_send` 失败就退出。修正为有界背压：Swift 专用发送线程等待容量；接收端收到容量通知后继续投递。保持队列上限、参考帧/输入边界顺序以及网络持续阻塞超时，真正停止时仍释放控制。新增具体传输关闭原因日志。
- 断开页面提供「重新连接」，按原应用的 bundle ID 在新会话的应用列表重新匹配，不重用旧主机分配 ID，也不重放旧输入。

## 中文输入法

原捕获过滤器只包含目标应用，无法包括独立输入法进程的候选窗。现在同时包含当前输入源的 bundle、系统输入法与标准 Input Methods 安装目录的输入法进程，以及系统文本输入辅助进程。新候选窗可随过滤器直接呈现；新启动的输入法进程通过更新过滤器加入，不重建同尺寸视频。

源窗口检查间隔调整为 250ms。候选窗越出应用边界时扩大联合范围，并在同一应用窗口几何期间保留已扩展区域，避免候选词出现/消失反复触发画面和输入配置换代。拖动期间保持映射。不同输入法和候选窗归属仍需双机实测。
