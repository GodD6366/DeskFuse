# 剪贴板与连接恢复

## 同步语义

- 自动同步以每台设备的当前连接为边界。连接建立时记录当前剪贴板 changeCount；只发送此后新复制的内容，不在启动、唤醒或重连时补发旧内容。
- “立即同步”可主动发送当前内容，包括主动再次发送原先接收的内容；关闭自动同步不影响这次明确操作。关闭自动同步仍拒绝外来的内容写入。
- 两端协商 `CLIPBOARD_SYNC_V2`。`ClipboardUpdate` 内承载 `application/x-deskfuse-clipboard-sync-v2` 消息，包含双向随机连接 epoch、同步 ID、内容版本、完整内容哈希、分块偏移和确认结果。旧原生同步及旧分块格式不回退；身份、配对与数据库格式不变。
- 新连接交换并确认 epoch 后接受内容；握手期间的新复制可留在同一连接的待发送槽，连接变化则失效。每设备只保留当前复制任务。
- 系统剪贴板写入成功后才确认；文件引用完成安装后确认。收到相同同步 ID 的重试仅回复已有结果，不再写入。新复制淘汰未完成旧接收，并保留“已替代”结果，避免重试重新覆盖。
- 发送后的确认等待为 1、2、4 秒，最多重试三次；最后一次额外等待 4 秒确认。断线、新复制、关闭同步或取消任务立即使旧发送失效。文件正文保留独立顺序及完整性确认，不受最新内容替换机制合并。
- 编码、压缩、解码在后台进行，重活串行限流；提交前核对连接、复制版本及系统剪贴板版本。多个接收共用现有容量上限。

## 连接与输入

- 每设备一个有界应用发送器；实际完成结果通过独立回执返回，不依赖可能丢事件的 UI 广播。取消等待会取消排队或正在写入的对应消息。
- 应用发送器等待 QUIC 确认整帧送达后再发送下一帧，不把写入本机缓冲区当成完成。单帧发送上限 30 秒，调用方含排队回执上限 40 秒；文件最终成功仍以接收端完整性校验及剪贴板安装确认作为依据。
- 每 5 秒进行一次独立 Ping/Pong 探测，单次 2 秒超时、连续两次失败触发恢复。读取控制请求与应用数据解耦，应用消息仍按流创建顺序交付。
- Ping/Pong 使用高于正文的 QUIC 流优先级。每个控制流读取单帧后继续读到 FIN，避免完整帧因提前销毁接收流而被重置。
- 重连沿用 1、2、4、8、16、30 秒退避。发送、探测和拨号清理绑定具体连接，不按过期 peer 结果关闭新会话。
- 输入链路每设备只有一个受管理重建任务；失败回到状态机，停用、权限不可用、断线、撤销或退出时取消并回收。保持原有 1.5 秒输入租约、可靠状态事件及最新位置 Datagram 策略。
- 发送器空闲退休与入队互斥；退休后的新消息使用新发送器。取消信号对晚开始等待的任务仍有效。
- 断线使旧文件接收、源引用和粘贴意图失效；不会恢复自动粘贴，也不重放按键或鼠标动作。

## 验收清单

针对性回归用例覆盖：逐设备连接基线、显式发送、确认丢失去重、旧 epoch 拒绝、旧分块被新复制淘汰、取消传递至发送器、结果不依赖 UI 广播、旧连接清理不影响新连接、发送器空闲竞争、晚等待任务取消、重建任务取消回收。

两机另行验收：睡眠唤醒、网络切换、对端重启、部分设备离线、连续复制、大图片、文件粘贴中断、拖拽时断网、恢复后重新跨屏。构建或包完整性检查不代表这些场景通过。
