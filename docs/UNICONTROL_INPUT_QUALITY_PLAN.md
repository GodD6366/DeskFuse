# DeskFuse 输入流畅度与多端输入能力开发文档

## 1. 文档目的

本文记录借鉴 Unictrl 后，DeskFuse 当前尚未完成或仅完成部分的工作，作为后续开发、评审和验收依据。

目标是让跨设备键鼠共享具备：

- 可独立演进的跨平台输入协议；
- 稳定的高频鼠标移动传输；
- 可观测的端到端流畅度；
- 面向用户的、能解释原因的优化建议；
- macOS 与 Windows 一致的能力和诊断体验。

## 2. 当前状态

### 2.1 代码里已经接上的部分

- 已有 `INPUT_MOTION_DATAGRAM_V1` 高频绝对坐标通道，可靠输入路径仍作为 fallback。
- 相对运动 datagram 前缀为 `DFR\x01`。字段是 `session_id`、`token`、`state_epoch`、`motion_seq`、`dx`、`dy`。单位是设备计数，`+x` 向右，`+y` 向下。非有限值或绝对值超过 32768 的增量会被拒绝。
- 能力位 `INPUT_RELATIVE_MOTION_V1`。默认同时广告 datagram 和 relative。`absolute` 只广告 datagram。`reliable` 不广告高频通道。探针仍只走绝对坐标，不广告 relative。
- 会话协商：双方有 datagram、对端声明 relative、本机原始采集就绪且对端注入就绪时使用相对移动。只有 datagram 时回退绝对坐标，并写明原因。否则走可靠路径。续租不升级模式。
- 相对增量在发送槽、接收槽和投递队列里按序号累加。超过上限的和不合成成一个超大包。没有原始增量时仍发绝对坐标，不用像素差冒充设备计数。
- macOS 用 CGEvent 整数 delta 作为相对采集。隐藏光标时保留；可见光标按位置刷新时清掉。事件钩安装成功才标记采集就绪。注入从当前光标加 delta，保留小数残差，未定位时不注入。
- Windows 在低级钩子之外注册 Raw Input。注册失败不中断绝对捕获。设备计数挂到下一次鼠标移动。注入使用不带绝对标志的 `SendInput`，残差留在注入线程。
- 阶段计数覆盖采集排队、发送和注入。报告里的端到端时间是这些阶段加上已有 RTT 的估计，不是两台机器对钟。呈现时间固定标为不支持。
- Windows helper 把本进程的采集排队和注入耗时放进已有的 `PollInput`。服务只在返回 `InputPoll` 时收下；拒绝或管道失败时 helper 把计数加回去。发送和 RTT 仍来自服务进程。
- 建议包含触发指标、可执行动作、预期改善和复测方式。历史最多 16 份。诊断导出会写本进程报告；macOS 输入子进程把同一份报告附加在已有诊断文本里，不写回滚动日志，并且最多每秒重算一次。
- macOS 流畅度卡片保留曲线，并显示模式、回退、慢注入、空态、异常和无权限说明。屏幕布局的最小高度仍是 480。Windows 输入页显示摘要、P50/P95、卡顿、模式、建议和曲线。
- 物理尺寸归一化仍是只读计算，默认不改变注入。

### 2.2 代码已写、尚未验证

本轮只改代码，没有运行 `cargo check`、`cargo test`、`cargo clippy` 或打包。下面不是测试通过记录。

- 协议和协商的单元测试意图已经在仓库里，但本轮没有执行。
- 没有做 macOS 与 Windows 双设备长跑，也没有做 125/500/1000 Hz、弱网、休眠唤醒、显示器热插拔、权限拒绝后恢复、签名或公证。

### 2.3 仍未完成

1. 真实 macOS ↔ Windows 双设备验收，以及上面列出的频率、弱网、热插拔和权限恢复。

## 3. 开发原则

- 协议只传输输入所需的数据和必要的诊断元数据，不传输坐标历史、按键内容或用户隐私数据。
- 相对运动和绝对坐标必须有明确的会话能力协商，不能通过猜测切换。
- 诊断数据必须有固定容量和时间窗口，禁止无限增长。
- 可靠 fallback 继续保留，任何新路径不可破坏现有输入。
- 平台层负责采集和注入差异，协议层只表达跨平台语义。
- “CI 通过”与“双设备实机验收”分开记录。

## 4. 分阶段开发计划

### 阶段 A：完善协议和能力协商

#### A1. 增加相对运动消息

新增独立于当前绝对坐标 `MotionPosition` 的消息类型，例如：

- `RelativeMotion`
  - `dx`
  - `dy`
  - `motion_seq`
  - `state_epoch`
  - `session_id`
  - `token`

要求：

- 明确单位和坐标方向；
- 拒绝 NaN、无穷大和超大增量；
- 每个会话维护单调递增序号；
- 保持与现有绝对坐标消息的版本兼容。

#### A2. 增加能力协商

增加能力位或会话字段：

- 是否支持 relative motion；
- 是否支持 absolute motion；
- 当前选用模式；
- fallback 原因；
- 对端版本和协议版本。

验收：

- 新旧版本可以建立可靠输入；
- 对端不支持 relative motion 时自动回退；
- UI 可以明确显示当前模式和回退原因。

### 阶段 B：平台输入抽象

#### B1. macOS

研究并实现：

- CGEvent 相对移动事件采集；
- 必要时接入 HID 级别原始增量；
- 鼠标捕获、隐藏、恢复和跨屏边界切换；
- 退出会话时恢复本地光标状态。

#### B2. Windows

研究并实现：

- Raw Input 鼠标增量采集；
- 与现有低级鼠标钩子或窗口消息路径隔离；
- 多显示器、负坐标、DPI 缩放和高精度鼠标处理；
- 注入端使用 SendInput 或等价路径恢复相对移动。

验收：

- 125/500/1000 Hz 鼠标在两端移动不明显丢步；
- 相对模式下不依赖屏幕分辨率；
- 屏幕边界切换仍由 DeskFuse 会话层控制；
- 权限不足时明确降级到绝对坐标或可靠路径。

### 阶段 C：物理尺寸与移动归一化

#### C1. 归一化模型

基于：

- logical frame；
- scale factor；
- physical width/height；
- display rotation；
- pointer sensitivity；

定义统一的物理移动模型。

建议先实现只读诊断和 A/B 对比，再默认启用自动归一化。

#### C2. 多显示器验收

覆盖：

- 不同 DPI；
- 横竖屏混排；
- 负坐标屏幕；
- Retina 与普通显示器混用；
- 不同物理尺寸但相同逻辑分辨率；
- 热插拔和拓扑 generation 变化。

## 5. 端到端质量诊断

### 5.1 采样点

为每个输入会话定义可选采样时间戳：

1. `captured_at`
2. `queued_at`
3. `sent_at`
4. `received_at`
5. `injected_at`
6. `presented_at`（平台支持时）

默认只记录聚合值或采样 ID，避免保存高频原始轨迹。

### 5.2 核心指标

- RTT P50/P95/P99；
- 端到端输入延迟 P50/P95；
- motion datagram 丢包率；
- motion 替换率；
- receive queue 深度；
- 发送和接收卡顿次数；
- 注入耗时；
- 光标呈现间隔和抖动；
- 当前刷新率和显示器拓扑变化次数。

### 5.3 诊断窗口

- 默认最近 60 秒；
- 固定容量 ring buffer；
- 无输入时显示空状态；
- 输入停止后保留最近窗口；
- 会话结束时清理或归档聚合数据；
- 诊断刷新频率不高于 1 Hz。

## 6. 优化建议引擎

建议按原因生成建议，而不是只按单一阈值生成：

| 诊断结果 | 建议 |
| --- | --- |
| P95 RTT 高，丢包低 | 检查 Wi-Fi 路由距离、网络拥塞和有线连接 |
| 丢包或替换率高 | 优先使用有线网络，检查无线干扰和接收端负载 |
| 接收队列持续增长 | 降低采样压力，检查事件循环和 CPU 占用 |
| 注入耗时高 | 检查辅助功能/Input Monitoring 权限和本地系统负载 |
| 只有呈现抖动高 | 检查显示刷新率、屏幕录制负载和窗口合成 |
| 物理尺寸缺失 | 使用逻辑坐标并提示无法进行物理归一化 |
| relative motion 不可用 | 显示具体平台、权限或版本原因，并说明当前 fallback |

每条建议应包括：

- 触发指标；
- 用户可执行动作；
- 预期改善指标；
- 操作后重新测量结果。

## 9. 完成标准

代码侧已经覆盖的最低标准：

- relative motion 有正式协议和能力协商，不支持时回退绝对坐标或可靠路径；
- macOS 使用 CGEvent 整数 delta，Windows 使用 Raw Input，两边都能相对注入；
- 两端界面都能显示质量曲线和当前模式；
- 诊断能区分网络、队列和注入，并说明呈现时间不可用；
- 优化建议带有触发指标、动作、预期和复测方式。历史对比写在诊断导出里；
- Windows helper 的采集排队和注入耗时通过 `PollInput` 进入服务报告。
