# 剪贴板列表与快捷粘贴

## 数据与保留

Rust 的 clipboard_library 使用 canonical `state.sqlite3` 中独立 `cl_*` 表保存普通历史、手动归档、列表、成员关系、设置和同步操作。普通历史默认 30 天、可配置天数、不限制条数；查询/恢复时逻辑隐藏到期记录，后台分批执行物理清理，面板关闭不暂停保留期。原始多格式快照按内容哈希单独存储，保持 SnapshotV1 二进制编码，不将 Swift 显示摘要作为恢复内容。原历史一次性迁移；没有复制日期的旧记录仅以导入时间计算宽限期，不显示虚构复制时间。

手动列表归档与普通历史行分离，多列表引用同一归档；离开最后列表后释放内容引用，删除列表不影响其他列表或用户源文件。智能列表动态筛选全部仍保存的内容，不延长普通历史期限。数据库分页仅返回摘要，图片和原始内容按选中/恢复请求读取。

每条记录可有用户标题，存于 `cl_items.title`，空表示未设置；显示时回退到来源 App 名称或内容短标题，清空标题即删除自定义值。标题通过 `set_item_title` 操作修改，不改变摘要、原始内容、搜索文字或同步操作。

列表条件采用全部/任一匹配：App bundle ID、来源设备 ID、内容类型、包含/不包含文字及本地日期。未知元数据不猜测。前端使用系统 Calendar 为日期规则构造闭开区间，包括 DST 和跨日；Rust 执行匹配。搜索使用完整文字，先筛选再分页。

## 跨设备

所有已配对且建立可信连接的设备交换独立列表协议；普通实时剪贴板开关不控制列表归档同步。列表定义、排序、归档元数据、成员操作及文字/图片原始格式同步；普通历史不会因重连整体补发，也不会把同步列表写入系统剪贴板。

列表协议在 `Hello` 中协商 `operation_chunks` 能力。超过 320 KiB 单帧上限的操作按 128 KiB 原始字节分块发送，接收端在分块到齐、SHA-256 校验和操作落库后才推进游标；单条完整操作最多 16 MiB。完整搜索文字和操作身份保持不变，长索引不会阻断后续手动列表成员操作。旧端仍使用原有小帧；遇到大操作时明确提示对端升级，不跳过或丢弃同步操作。

普通历史另有一层可检索的 `index:` 同步：本地普通记录在入库、改标题、OCR 完成后发布紧凑索引（摘要、标题、识别文字、搜索文字、`blob_hash`），对端落为“远端索引行”（`remote=1`、`payload IS NULL`），按 `global_id` 与 `digest` 合并，不覆盖本地行，也不按 OCR 内容去重。索引体积小、可整体补发搜索；图片/文字正文不随索引推送，UI 需要时调用 `want_item_payload`，由 `library_sync` 按 `blob_hash` 分块拉取并在校验后填充该行 payload。索引发布只覆盖更新后新产生的记录，旧历史不回填。

设置项 `sync_index`（默认开启，存于 `cl_meta` 的 settings）控制这层索引：关闭后不再发布本机索引、也不再物化对端索引行（已存的操作记录保留，重新开启时 `reconcile_index` 重新物化）；“清除已同步的远端索引”删除本机 `remote=1` 的行，不影响本机历史、手动列表或已获取的正文。

持久操作 UUID 用于去重，本机递增 seq 仅用于日志分页；逻辑版本、作者和因果信息决定冲突。列表删除保留墓碑，旧编辑不得复活；成员并发删除优先，已观察到删除后的显式重新添加有效。内容按摘要请求并分块校验，未到齐时保持不可粘贴状态；正文完整包含在同步摘要中的短文本（预览未被截断）可直接恢复使用，并在使用时仍按需拉取原始格式。旧端缺少策略版本时提示升级，不回退到可能保存被排除内容的旧路径。

普通历史按内容摘要归并：纯文本按 NFC 和换行归一化后的文字计算摘要，因此同一段文字的富文本本地捕获、精简同步接收和接力回写复用同一行；图片与文件仍用完整格式摘要，避免按名称误合并不同内容。删除普通历史同时删除同一 global id 的手动列表归档；归档删除写入 `item:` 墓碑，后续合并不得复活。

远端写回系统剪贴板使用 `CurrentHostOnly`（不进 Universal Clipboard）并写入 `com.deskfuse.clipboard-origin` marker。系统接力带有 `com.apple.is-remote-clipboard` 时直接作为系统回声跳过入库和广播；系统剥掉该标记或接力先于 DeskFuse 到达时，另由 10 秒、最多 512 条的等价指纹账本兜底：文本含归一化别名，图片含字节摘要和 dHash，本地捕获与远端写入共用，命中任一键即视为回声。历史取用仍写入本机剪贴板；10 秒内相同内容不再向对端重复广播。

## 文件归档

文件归档只同步稳定资源 UUID、来源设备、名称、大小及 manifest 摘要；本机源路径存于本机资源表，不作为另一台设备的可访问路径。显式使用时重新核对来源内容，创建新的请求和连接代次，遵循现有缓存配额、文件结构及原子接收规则。

源文件删除、移动、内容变化、设备离线或请求取消均明确失败。原始用户文件从不由列表清理删除；不通过长期固定全部文件缓存来承诺无限文件保存。文件接收完成不代表自动粘贴成功，只有当前有效请求才安装文件 URL。

## 排除 App

本轮只提供按 App 排除，配置各设备独立，以 bundle ID 去重。新本地复制附带来源 App/设备/时间和 no_history；接收端沿用原来源，不使用自己的前台 App 冒充。发送端排除或接收端排除均阻止新历史保存，但仍安装实时系统剪贴板；文件准备所需临时缓存继续按原生命周期管理。新规则不追溯删除已有普通历史或手动归档。

## 唤起与粘贴

默认 Option+Command+V，可修改或关闭。状态栏图标与全局快捷键共用同一 SwiftUI 内容和会话，同一时刻只显示一个原生容器：图标点击锚定状态栏，全局快捷键在鼠标所在屏幕旁展开；空间不足时翻到左侧并限制在屏幕可用区域。面板目标高度 780 pt，小屏自动收缩。双击、回车、Command+1–9 使用当前结果；单击/方向键仅选择，输入法组字不抢键。

引擎在串行恢复操作内返回准确 pasteboard change_count。原生层随后激活打开前的应用、等待修饰键释放并核对原应用、会话与 change_count，才发送一次标记后的粘贴事件。新复制、会话失效、目标退出、权限不足均不能被解释为成功。仅复制走同样内容准备但不发送按键。

搜索框聚焦时 Delete/Backspace 只编辑输入文字，不删除历史；点击条目或方向键把焦点移出搜索框后，Delete 才删除选中的历史记录。
