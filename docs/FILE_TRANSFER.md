# 文件复制、按需传输与缓存

状态：2026-09-05 用户确认的功能契约。本文件定义预期行为；运行证据另存于 `artifacts/validation/`。

## 使用路径

1. 本机复制文件/文件夹后，向可信已连接设备发布轻量文件引用。此时不读取完整文件、不打包、不发送文件正文。
2. 目标机器实际粘贴时，异步请求对应内容并显示准备、接收和完成进度。一次粘贴只创建一个任务；重复请求关联同一任务。完成完整性校验后，交给原生粘贴流程。
3. 任务关联确定的剪贴板版本和目标应用。新复制、过期、取消或断线使旧请求失效时，不能覆盖新剪贴板或把自动粘贴发给其他应用。
4. 抽屉菜单的显式“发送”仍立即开始传输。普通暂存和本地拖出不要求远端设备在线。

源引用在复制时只记录文件身份、大小、内容修改时间和目录结构；Finder 标签、扩展属性或权限引起的 Unix `ctime` 变化不作为内容修改。按需扫描前后仍校验源引用，接收完成仍验证完整内容哈希。显式发送在扫描结束、首个 Offer 发出前绑定当前连接；响应粘贴请求始终绑定原连接。任务开始发送后，正文和取消帧都不能跨到重建的新连接。

## 连接中断

自动同步只发送当前连接建立后的新复制；重连不补发旧内容。旧文件接收与自动粘贴意图在断线时失效，需要重新复制或显式重新发送。文件引用安装确认、逐连接取消和大图片分块规则见 [剪贴板与连接恢复](CLIPBOARD_STABILITY.md)。

## 剪贴板历史持久化

- 本机 SQLite 数据库 `~/Library/Application Support/uniDesk/state.sqlite3` 保存最近 50 条剪贴板历史，包含来源、完整文字、图片、原始多格式内容和文件引用；预览从原始内容生成。
- 新复制、去重置顶、历史淘汰和清空同步写入数据库，启动恢复原有顺序；恢复列表本身不写系统剪贴板，也不重新向其他设备发送历史内容。
- 文件内容仍由现有源文件和传输缓存管理，不额外将文件正文塞入数据库；路径失效时沿用明确的不可用提示。缓存清理删除相关历史记录时同步更新数据库。
- 数据库写入或恢复失败显示错误，不记录剪贴板正文；数据库文件仅当前用户可读写。

## 小文件提前传输

- 作为可关闭的独立配置；默认关闭，以粘贴时传输为默认体验。
- 阈值默认 10 MiB，可配置并持久保存。界面明确单位，按整批实际总字节数判断，文件夹递归计算，未知大小按需处理。
- 开启后，阈值内文件可提前接收；目标机器后续粘贴复用校验后的缓存。
- 配额不足或无法确认大小时保留按需引用，不为提前传输驱逐活跃数据。

## 最大占用与清理

- 缓存上限可配置并持久保存，初始建议 1 GiB。计入应用管理的临时/接收/完成文件；分块写入前检查配额，并发任务不能重复消费同一剩余额度。
- 对可回收的历史内容按时间回收。当前粘贴、接收、导出以及仍需使用的文件具有明确生命周期保护；活跃内容超过可用额度时暂停接收并提示容量不足。
- “清除历史传输文件”释放应用缓存，不只删除 UI 记录；显示当前占用、释放字节、保留活跃任务和失败情况。
- 只能删除应用私有缓存根目录内由应用管理的内容，拒绝符号链接逃逸。用户原始文件、导出文件和 Finder 粘贴后的副本不受清理影响。
- 清理旧缓存后，历史记录仍可表示该次传输，但不再承诺本地文件可用。再次使用需重新请求或明确告知来源已失效。

## 验收场景

- 大文件复制后、粘贴前：无文件正文传输且无大规模预读；目标粘贴才开始，显示实际进度并校验结果哈希。
- 开启/关闭提前传输、阈值上下边界、多文件和文件夹总量、重启后配置保留。
- 同一引用重复粘贴、源文件变化/删除、目标应用切换、新复制替换旧引用、取消和断线恢复。
- 单任务/并发配额、接收中的历史清理、缓存目录符号链接、清理失败、原文件/目的地内容完整性。
- 原生 Command-V、菜单粘贴和右键粘贴分别记录实际支持范围，不能以单元测试模拟请求宣称全部原生粘贴入口已验收。
- 测试使用独立临时目录和生成样例；用户实际历史缓存不会在自动验收时被清空。
