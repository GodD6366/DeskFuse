## 当前结构

- 主窗口为单实例 `NavigationSplitView`，功能侧栏包含剪贴板、键鼠共享、设备、传输。
- 剪贴板为功能侧栏、历史列表、内容预览三栏；侧栏理想宽 180 pt，历史栏初始宽 260 pt、可在 240–320 pt 内拖动调整，预览吸收剩余空间。所有分栏铺满可用高度，不能依赖列表内容的最小尺寸。
- 列表含页面标题、副文、搜索、内容类型和来源筛选、真实历史及底部同步开关。初次进入选中首条可见历史；只读取预览，不自动恢复系统剪贴板。筛选为空时呈现真实空态。
- 预览含标题、来源、大小、文件可用性、图片/文件/文本内容及底部格式信息。图片保持比例，提供适合窗口或填满预览；文本和文件列表底部留出滚动空间，不被操作条遮挡。
- 设置独立为系统 `Settings` 窗口，支持 ⌘,。
- 正常窗口 1200 × 780 pt，最小 960 × 620 pt；侧栏可折叠，正文可滚动。
- 设备列表底部同时提供手动 IPv4 配对，保留自动发现和接收方确认。设备详情展示完整连接候选列表（地址、发现来源、健康状态），并区分当前活动地址与下次优先候选；离线时不把第一条候选当作当前连接。优先路径是类型偏好而不是 IP 绑定，候选不等于已连通，不根据 IP 前缀猜测雷电/Wi-Fi 类型。
- 键鼠页围绕真实显示器布局和实际可用性展开；开关、权限和已就绪分别展示。
- 方形暂存区保持独立、不夺焦点的 240 × 240 pt 面板，展开 480 × 420 pt；发送是二级设备菜单。

## 菜单栏最近剪贴板（2026-09-12）

用户已确认按 [Atelier 菜单栏设计稿](10-menubar-clipboard.png) 开始实际开发；[来源与校验记录](menubar-clipboard-manifest.json)保留生成标识及设计图检查边界。以下为当前行为规范，不是新增主窗口页面，也不替代独立文件暂存区。

- 菜单栏使用原生窗口式面板，目标 440 × 660 pt，小屏收缩列表；搜索、类型和来源设备筛选、最近最多 20 条记录、固定查看全部/复制操作条。
- 图片按需后台读取并限制缩略图长边为 320 px；文字、文件与文件夹使用真实预览及元数据。文件历史的 `length` 是引用数量，不显示为文件字节大小。
- 打开默认选中第一条可见记录；⌘F 聚焦搜索。无历史或无匹配时显示真实空态并禁用复制，无匹配时可清除筛选。单击或方向键只选择；回车、复制按钮和当前面板内的 ⌘1–9 执行恢复。收到引擎 `CommandApplied` 后才关闭；失败保留错误；旧会话回调不能关闭重新打开的面板。Esc/点外关闭，输入法组字期间不抢快捷键。
- 查看全部进入主窗口剪贴板并转交搜索、类型、来源和选择；完整内容搜索仍由 Rust 处理。
- 复制时间由 Rust 在实际记录事件时捕获并持久化。旧记录无时间时不生成“刚刚”或虚构分钟数；恢复/启动读取不是新复制事件。数据库增加 nullable 时间列，保留原始剪贴板快照编码与历史。
- 暂存区保留快捷入口；更多菜单保留运行状态、打开主窗口、收回键鼠、设置和退出。头尾复用原生材质与现有可访问性回退，正文使用稳定底面。
- 交付证据见 `artifacts/validation/2026-09-12-menubar-clipboard/`。按默认流程仅构建、签名、DMG 与 NAS 完整性检查，尚不构成实际菜单栏视觉/键盘操作、Finder 或两机验收。

## 键鼠布局补充基准（2026-09-11）

用户确认按[旧实现布局截图](assets/input-layout-reference.png)开始实现键鼠共享页的屏幕布局：点阵画布、简单描边矩形、极浅填充，不画壁纸、设备机身、底座或支架。显示器尺寸与坐标使用引擎真实布局，不把参考截图中的三块屏幕写死成演示数据。矩形内部必须显示顺序编号、设备名称、宽 × 高尺寸；尺寸使用引擎逻辑桌面数据并标注 pt，不冒充物理英寸。画布外图例同步编号、设备名、尺寸、就绪状态，悬停可查看设备信息；按设备身份分配不同颜色，同一设备的屏幕保持相同配色；本机以文字标识，未就绪使用虚线及文字区分，不沿用参考图的橙红色作通用边框。同一设备多屏仍整体拖动。

正常宽度下画布位于左侧、设备可用性检查器位于右侧；窄窗口将检查器移到画布下方并允许滚动。编号按稳定设备/显示器 ID 排序生成，仅为当前布局标识，不冒充系统显示器编号。

## 主控布局与被控状态（2026-09-12）

- 屏幕画布、设备颜色、拖动布局和共享设置只在主控电脑显示。被控电脑只显示被控状态及“停止被控”按钮；未连接时展示等待状态，停止后展示已停止状态。不向被控端同步可编辑布局。
- 主控界面和鼠标穿越使用同一 Rust 布局解析器。拖动时提供边缘磁吸预览，松手时贴合最近的不重叠共边，避免缝隙、重叠或仅角点接触导致不能穿越。同一设备的原生多屏相对位置不变，保存时保留所有可见设备的位置，离线设备位置不丢失。
- 调整布局只更新路由几何，不关闭原生输入可用性，不重新启动权限适配器或创建主控激活意图。涉及正在控制的屏幕时仍释放当前输入并安全收回，不能保留旧坐标继续注入。
- 本轮仅按默认流程完成构建、签名和包检查，真实两机往返穿越、停止被控、断线重连及窗口视觉验收仍需单独记录。

## 原生 Liquid Glass

- 标准侧栏、工具栏、设置和系统菜单使用 SwiftUI 自带材质，不覆盖自绘玻璃背景。
- 工具栏用 `ToolbarSpacer` 区分操作组；窗口使用系统 unified 工具栏，不覆盖自绘背景。
- 预览底部复制操作条、图片显示方式菜单使用系统 `glassEffect(.regular.interactive())`，共同位于一个 `GlassEffectContainer`；主要复制操作使用系统 `.glassProminent`。
- 侧栏本机状态、历史同步开关、文件暂存面板为独立的原生玻璃浮层。玻璃透色由系统、壁纸、窗口激活和可访问性设置决定，不硬编码图中的蓝绿光晕。
- macOS 26+ 使用原生 Liquid Glass。macOS 14/15 使用系统材质，开启降低透明度时浮层使用系统实色底面。
- 不使用 CSS、透明渐变、重复模糊层或屏幕截图来模拟系统玻璃。正文、文本和图片预览保留稳定内容区域。

## 行为与证据

[文件传输契约](../../docs/FILE_TRANSFER.md) 和 [抽屉规范](SHELF.md) 继续有效。UI 绑定 Rust 引擎真实状态，不提供假设备或演示进度。

构建、签名、包完整性及实际应用检查分别记录在 `artifacts/validation/`。旧版本的视觉结果不能沿用为当前版本的验收结论；Finder 拖放、复制结果和两机验收不能由 UI 检查或构建结果替代。

构建必须同时保留最低 macOS 14.0 和真实的 macOS 26+ linked SDK。仅写 `glassEffect`，但最终 Mach-O 错标旧 SDK，不构成原生玻璃交付；构建和 DMG 校验脚本均检查 SDK 标记。Debug 的 Window 菜单提供 1200 × 780 和 960 × 620 pt 两个真实窗口尺寸，便于复现视觉检查；Release 不包含这些菜单。

预览只对选中的图片进行后台解码，并限制缩略图长边；复制仍恢复 Rust 保存的原始内容。暂存区仅接受真实可用的本地文件，沿用现有导出租约；只有位图数据而没有文件 URL 的图片不会伪装成可暂存的本地文件。

[架构文档](../../docs/ARCHITECTURE.md) 记录当前接口和模块职责。
