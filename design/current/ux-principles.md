# DeskFuse 交互原则（Don't Make Me Think）

> 2026-10-22 梳理。新增或修改界面前先对照本文；与 `ui-refresh-verification.md` 的视觉契约互补。

## 三条底线

1. **不用想就会用**：每个页面一眼能回答「这是哪里、能做什么、下一步点哪」。
2. **出错不迷惑**：任何错误提示都说清「发生了什么 + 用户现在能做什么」，内部原文只放进「复制详情 / 反馈问题」。
3. **随时能找到开发者**：无论用户在主窗口、菜单栏面板、错误提示还是启动失败页，同一个「反馈问题」入口都在一步之内。

## 1. 流畅、符合直觉

| 原则 | DeskFuse 中的落地 |
| --- | --- |
| 显而易见优先于聪明 | 功能页关闭时只有一种状态：`FeatureOnboardingView` 演示 + 「启用 X」按钮，与右上角总开关是同一动作；总开关旁直接写出「已开启 / 已关闭」。 |
| 第一步放在最前面 | 还没配对任何电脑时，侧栏把「设备」分组放到最上方；配对后恢复「基础 → 高级 → 配置」的顺序。 |
| 惯例优于创新 | 系统菜单「帮助」必须可用；不保留会弹出“帮助不可用”的默认项。快捷键沿用 macOS 惯例（⌘, 设置、⌘? 帮助、⌘F 搜索）。 |
| 同一事物同一叫法 | 设备状态统一用「在线 / 未添加」；侧栏、健康中心、反馈环境信息使用同一措辞。 |
| 去掉要读的字 | 侧栏底部只显示一句整体状态；问题清单点开才出现，每条问题自带唯一的下一步按钮。 |
| 一件事只放一处 | 诊断导出只在「设置 → 关于与更新 → 帮助与反馈」；「高级」只保留版本信息和日志文件夹。所有全局快捷键（剪贴板面板、工作流、键鼠、固定组合）都在「设置 → 快捷键」，修改立即生效；工作流是独立的设置分类，不再藏在剪贴板设置的分段选择器里。 |
| 空状态给出下一步 | `DFEmptyState` 必须写明「为什么是空的」和一个主要动作；启动失败页提供「重试」与「反馈问题」。 |

## 2. 异常信息

- 所有展示给用户的错误文本经过 `friendlyError(_:)`：已知英文内部错误映射为可理解的中文说明；已经是中文的提示原样显示；未知英文错误显示通用说明并指向「帮助 → 反馈问题」。
- 原始错误只在以下位置出现：`ErrorNoticeView` 的「复制详情」、反馈页预填正文、诊断文件；功能页的诊断详情（如键鼠链路质量）可保留原文。
- 可操作的错误不自动消失（`ErrorNotice`），关闭后同一条运行时错误不会因重复快照而复活。
- 错误提示的按钮顺序：先自助（复制详情 / 前往授权 / 重试），后求助（反馈问题）。

## 3. 联系开发者

统一入口为 `SupportCenter`（`apps/deskfuse-macos/Sources/DeskFuse/SupportCenter.swift`），反馈、发行版与源码都在公开仓库 `GodD6366/DeskFuse`：

1. 引擎把运行记录、输入时序、链路质量，以及界面层的内存和鼠标诊断拼成一份 JSONL，**统一脱敏**后写到 `~/Library/Logs/DeskFuse/DeskFuse-diagnostics-<时间>.jsonl`。
2. 打开新 Issue，标题和正文已预填：界面错误原文（已脱敏）、版本与通道、macOS 版本与架构、当前页面、配对与在线数量、健康状态，以及折叠的**诊断摘要**（版本、各子系统记录数、链路质量、最近 20 条告警与错误）。链接总长控制在 7500 字符以内，超出时先裁最早的摘要行。
3. 在访达中选中完整的脱敏诊断文件，开发者需要时用户再拖进 Issue。
4. 后台服务未就绪时，摘要改用最近日志末尾 40 行，同样先脱敏。

### 脱敏规则（`crates/deskfuse-engine/src/diagnostics_redact.rs`）

| 信息 | 处理 |
| --- | --- |
| 本机名、主机名 | `<this-device>` |
| 其他电脑名称 | `<device#N>` |
| IPv4 / IPv6 | 保留类别和端口：`<ip:lan#N>`、`<ip:public#N>`、`<ip:loopback>`；`0.0.0.0` 保留 |
| 设备 ID 等 16 位以上 hex | `<id#N>` |
| MAC、邮箱 | `<mac>`、`<email>` |
| 用户目录 | `~` |
| `display_name`、`hostname`、`ssid`、`account` 等键的值 | 已知名称用对应代号，其余为 `<redacted>` |

同一次导出内，同一原值始终对应同一代号，仍能看出“是不是同一台设备、同一条链路”。请求 UUID、版本号、时间戳和网卡名不含个人信息，保留以便排查。新增诊断字段时，如果可能含个人信息，必须补充规则和测试。

### 入口位置

| 位置 | 入口 |
| --- | --- |
| 菜单栏「帮助」 | 反馈问题…（⌘?）、导出诊断信息…、复制版本与环境信息、已报告的问题、发行说明、安全问题反馈 |
| 主窗口侧栏底部 | 状态右侧固定的问号菜单；状态弹层底部「遇到问题？反馈问题…」 |
| 窗口错误提示 | 「复制详情」旁的「反馈问题…」，自动附带该条错误原文 |
| 健康中心「后台服务出现问题」 | 主要动作即「反馈问题」 |
| 启动失败页 | 「重试」+「反馈问题…」 |
| 菜单栏剪贴板面板 | 更多菜单中的「反馈问题…」 |
| 设置 → 关于与更新 | 「帮助与反馈」分组：反馈问题、导出诊断、已报告的问题与发行说明 |
| 安装窗口 | 「安装遇到问题？立即反馈」 |
| Windows 设置窗口、托盘菜单 | 「反馈问题…」预填版本、系统与服务状态；暂不导出诊断，正文提示不要附原始日志 |
| 官网页脚 | 「反馈问题」 |
